# Project documents: the organisation's templates in PMS

Every project has a **Documents** tab that lists the organisation's templates in the order the lifecycle needs them.
For each one it shows where it stands, with one button to write it, continue it, print it or open it.

| Template | Where it lives in PMS | Lifecycle stage |
|---|---|---|
| **Project Concept Note (PCN)** | The Concept Note on the project's Overview (same sections as the template: background, concept, mechanics, objectives, main and supporting pillars, proposed dates, signatories) and its printable page | 1 PCN Draft, 3 PCN Sign Off |
| **BRS**: Business Requirements Specification | Written in PMS from the template: document control, executive summary, contributors, approvals, history, introduction, objectives, business projections, functional requirements (FRN-01, FRN-01-01… with M/S/C/W priority), integration requirements (IRN-001…), testing requirements, process flow | 5 BRS Draft, 6 BRS Sign Off |
| **BSS**: Business Solution Specification | Written in PMS from the template, with its standard content ready to edit: scope, architecture, solution stack, deliverables, FRN-001… modules with sub-features (business process, description, benefits, pre-conditions, actors, triggers), NFRN-001–010, SECN-001–014, security headers, RRN-001–009, testing, documentation, deployment, appendices, document control | 7 BSS Draft, 8 BSS Sign Off |
| **UAT script** | Printed from the project's UAT test cases: scenario, test #, test case, test user(s) assigned, expected result, result (Pass / Fail / Waived), comments, and the results chart | 13 UATs |
| **Change Request form** | The Deployment stage's record: every field of the form (request, the change, technical details, risk and impact, the three approvers, change closure), printed in the form's layout | 14 Deployment |
| **Release Notes** | Written in PMS from the template; bug fixes and finished features are filled in from the work items resolved since the last release | 15 Post Deployment Testing, 16 Close Project |
| **Changelog** | Built from the published release notes (version summary; Added, Changed, Deprecated / removed, Fixed, Security) | All releases |

## How it works

1. **Write:** open the document from the Documents tab, or from **Write it in PMS** on the stage. A new draft is
   prefilled with what PMS already knows: the project's name, today's date, you as the author, and the Concept
   Note's background, concept and objectives. Every change is saved as you type.
2. **Preview / print:** **Preview** shows the document in the template's layout, under the organisation's
   letterhead. **Print / Save as PDF** gives the PDF.
3. **Submit:** **Submit as the BRS for sign-off** freezes this version and makes it the stage's deliverable (BRS v1,
   v2…). The stage's sign-off is then requested as usual. Whoever submitted it can't sign it, and the signed version
   is locked. The printed Approvals table shows who signed and when.
4. **Change it later:** a submitted version is never changed. Opening the document again starts the next version
   from the last one.

Uploading a Word or PDF file instead still works: both count as the same deliverable.

## Not included

- The Econet logo on the templates: printouts carry the organisation's own letterhead (logo and name) from its
  branding.
- Word (.docx) export: documents are printed or saved as PDF from the browser.
